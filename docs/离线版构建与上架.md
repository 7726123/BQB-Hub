# 干净版（离线版）：构建与上架

一份**不含我方服务器**的构建：没有社区 / 账号 / 在线更新 / 网页包热更新 / 埋点 / 反馈 / 管理端，
只保留本地写作功能与"用户自己配的模型 API"（BYOK）。目标是国内应用商店上架（见文末清单）。

**叫法**：应用名（桌面图标下、商店列表、软著、App 备案要一致的那个）是 **「BQB-Hub」**；
"干净版 / 离线版"只是工程内部叫法，**不出现在任何用户可见的地方**——用户看到的措辞统一是"本版本"。

完整版（官网直发渠道）**不受影响**，两个版本同仓库、同源码，靠一个构建期开关分叉。

---

## 1. 与完整版的关系

| | 完整版（官网直发） | 干净版（商店） |
|---|---|---|
| 包名 | `com.novelwriter.app` | `com.bqbhub.app` |
| 构建产物 | `web/` + `android/` | `web-clean/` + `android-clean/` |
| 社区/账号/IP 直连/更新检查/热更/埋点/反馈 | 有 | **全部没有（代码早退 + 入口摘除）** |
| 应用内更新 | 下载安装 APK + 网页包热更 | 无（只提示去应用商店） |
| 模型 API | 用户自配（默认 DeepSeek） | 同上 |
| 源码 | 同一份（`app/src`，`web/index.html` 共用） | 同上 |

开关：`app/src/lib/buildflags.ts` 的 `isClean()`。干净版构建时由 esbuild
`--define:__BQB_CLEAN__=true` 注入（完整版不注入 = false，行为与历史完全一致）。

## 2. 构建（三条命令）

```bash
# ① 生成干净版 Android 工程（差异点都在这个脚本顶部，如包名/版本/应用名）
node scripts/make-android-clean.mjs

# ② 构建干净版网页包，并自动同步进 android-clean 的 assets/public
cd app && npm run sync:legacy:clean

# ③ 打包（需先配 release 签名，见下节）
cd ../android-clean && ./gradlew assembleRelease      # 调试包用 assembleDebug
```

产物：
- `web-clean/`：干净版网页包（`index.html`、`assets/`、`modules/main.js`、`version.json`）
- `android-clean/app/build/outputs/apk/<flavor>/app-*.apk`

两个目录都是**构建产物**（已 gitignore），随时可删可重建；完整版的 `web/`、`android/` 一行不动。

### 上架签名（还没配过）

商店只收 release 签名包（现在官网渠道发的是 debug 包，商店会直接拒）。**首次创建密钥后必须永久保管，
丢了就再也无法给已上架应用推更新**：

```bash
keytool -genkeypair -v -keystore ~/bqb-clean-release.jks \
  -alias bqbhub -keyalg RSA -keysize 2048 -validity 10000
```

把路径与口令写进 `~/.gradle/gradle.properties`（**不要入库**，`.gitignore` 已挡 `*.key`/`keys/`）：

```properties
BQB_RELEASE_STORE_FILE=/absolute/path/bqb-clean-release.jks
BQB_RELEASE_STORE_PASSWORD=***
BQB_RELEASE_KEY_ALIAS=bqbhub
BQB_RELEASE_KEY_PASSWORD=***
```

`android-clean/app/build.gradle` 已带这套脚手架（读得到属性就启用 release 签名）。

## 3. 代码里"剥离服务器"的点（改代码时的对照表）

一处开关 + 十处早退，每一处都有对应的测试（`app/tests/clean-mode.test.ts`）：

| 位置 | 干净版行为 |
|---|---|
| `lib/server-url.ts` | 服务器地址常量**在产物里被死代码消除**（不是"有地址但不调用"）；`defaultServerBase()` 返回空串（纵深防御：漏了守卫也打不到服务器） |
| `domain/update.ts` | 启动不检查更新、不启统计、不收启动画面；手动点「检查更新」只提示去应用商店 |
| `domain/hotbundle.ts` | `init/prefetch/check/applyPending/applyPendingNow/commitPending/_bindApplyHooks` 全部早退 |
| `domain/clientlog.ts` | 错误日志只留本机（localStorage + 控制台），`flush()` 不上报 |
| `domain/stats.ts` | `UsagePing.init()` 早退（无匿名统计、无心跳） |
| `domain/feedback.ts` | `submit()` 直接拒绝 |
| `domain/adminmode.ts` | `isOn()` 恒 false、`tap()` 恒 null、`sendTrace()` 早退（连点 10 下也进不去管理端） |
| `domain/community.ts` | `init/onEnter/searchCards/openAdminPanel/syncAdminEntry` 早退 |
| `domain/assistant.ts` | 工具表为空、`_executeTool` 拒绝、`_uploadMissed` 不上报；system 去掉找卡能力，手册换用离线版小节 |
| `domain/cleanui.ts` | 启动时从 DOM 摘掉社区/反馈/管理入口与找卡弹层，改写助手与设置页里"社区"字样，把「检查更新」改成商店提示 |

**助手手册**（用户最容易看到的地方）：`manualForClean()` 按小节覆盖 §十二（联机功能）/§十三（更新）/§十五（反馈），
再把零散提到联机的句子逐句改写（世界书导出、字号作用范围等）；**其余小节与完整版共用同一份文本**，
不是抄两份——手册是活文档，抄两份必然改一处忘一处。

### Android 侧（`scripts/make-android-clean.mjs` 生成时处理）

- 删 `REQUEST_INSTALL_PACKAGES` 权限（应用内装 APK 是商店红线）
- 删内置自签 CA（`res/raw/bqb_ca.crt`）与对应的域例外，网络安全配置只留系统 CA
- 删 `UpdateCheckerPlugin.java`（APK 自更新）、`HotBundlePlugin.java` + `HotBundleCore.java`（网页包热更）三类，
  并摘掉 `MainActivity` 里的 `registerPlugin`
- 改包名 / 版本号 / 应用名（应用名要与软著、商店名称一致，改脚本顶部的常量）

生成器末尾会自检：干净版工程里不允许再出现上述权限、CA、插件类名。

### 产物自检（`build-clean.mjs` 每次构建都跑）

1. 没有未替换的 `__BQB_CLEAN__`（否则开关没生效，这份产物其实是完整版）
2. **没有服务器地址字符串**（常量折叠 + 死代码消除真的生效了）
3. 产物里是干净版手册（如 `十二、联机功能（本版本没有）`）

> 说明：干净版产物里仍会保留少量**用不到的**中文文本（完整版手册原文、社区模块的提示语等）——
> 它们在正常路径上不可达，只是没被 tree-shaking 掉。行为干净、无地址、无权限、无请求。

## 4. 上架前还要做的（与代码无关）

1. **企业主体**：带账号/UGC 的服务才需要企业资质；干净版无账号无 UGC，个人主体通常可行（各省管局口径不一）。
2. **App 备案**（工信部，2023-09 起强制）+ 域名 ICP 备案（若还要自己发资源）+ 公安联网备案（开通 30 日内）。
3. **软著**：名称要与商店应用名一致；提交的源代码首尾各 30 页里不要出现露骨/违规内容。
4. **隐私政策**：干净版不收集、不上传任何数据（错误日志只留本机），隐私政策要如实这么写；商店要求填 URL。
5. **审核体验**：审核员没有模型 API Key，打开只能看到空壳 → 准备一段审核说明（"需在『高级设置 → 模型与密钥』
   填入任意 OpenAI 兼容端点后使用"），必要时给试用额度。
6. 应用名/图标/截图与软著一致；名称不要撞他人商标。
7. 应用商店选「工具/效率」类目（别选阅读/内容类，那会牵出出版资质问题）。

---

## 5. 干净版里没有的东西（别期待）

社区（世界书/预设的上传下载、评论、点赞）、账号、管理员后台、在线更新与热更、匿名统计、在线反馈。
这些只在完整版里；干净版的世界书/预设靠「导出 / 导入 JSON」在本机或聊天软件里传递。

## 6. 维护约定（两个版本怎么一起走）

**默认：一次改动、两个版本一起出。** 同一份源码构建两次：

```bash
cd app
npm run sync:legacy        # 完整版 → web/
npm run sync:legacy:clean  # 干净版 → web-clean/（并同步进 android-clean 的 assets）
```

- **只碰服务器的功能**（社区、账号、管理端、匿名统计、在线反馈、热更通道本身）：只有完整版有，
  干净版**不用动**——那些入口在干净版本来就早退/摘除了；改完顺手跑一遍测试确认没漏就行。
- **新增任何"会碰服务器"的代码**（新接口、新上报、新的第三方服务）时必须**同时**做两件事，
  否则干净版会带着请求出包：
  1. 调用点前面加 `if (isClean()) return …;`（返回类型不符就返回空值：`''` / `false` / `Promise.resolve(false)`）；
  2. 在 `app/tests/clean-mode.test.ts` 的"启动链路不发请求"用例里补一行调用。
- **改文案 / 助手手册**：手册是两个版本共用的活文档，干净版的差异只在 `assistant.ts` 的
  `CLEAN_SECTION_OVERRIDES` / `CLEAN_LINE_FIXES` 两张表里。改完整版小节内容不用动干净版，
  但**挪动了小节序号**（"十二、"这类）要同步改表里的键。
- **出包前自检**：`sync:legacy:clean` 自带三条断言（见 §3），`make-android-clean.mjs` 也有自己的自检；
  任一失败都会中断构建，不会悄悄产出"半干净"的包。
- **发版路径不同**：完整版走热更新 / 官网 APK；干净版走上架商店（商店版没有热更新通道，
  审核周期内只能靠"资源型内容"更新，代码改动只能等版本）。
