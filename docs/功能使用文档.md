# BQB Hub - 功能使用文档

> ⚠️ 本文档正在逐章校对（截至 2026-09）。前七章部分描述的是**已下线机制**：
> - 世界书条目类型已收敛为「世界观 / 角色 / 初始 / 其他」（「开头」类型 v1.5.81 起废弃，存量开头条目自动移除）——第 1.1、1.2 节的「变量 / 前端」条目类型入口已不可用；变量更新机制（续写输出 `[VAR]` 块）本身仍在运行。
> - 「条件注入」机制已整体移除（第 2 章、第 6.2 节不再适用）：当前所有开启「注入」的条目一律注入上下文，由检索与注入上限控制取舍。
> - 社区聊天（频道 / WebSocket）v1.5.82 起整体下线，社区只保留世界书与预设；API 的 Max Tokens 设置项同版本移除（输出上限不再由用户设置，一律按端点能接受的最大值发送）；世界书注入上限固定 10 万字（见第九章第 6 条）。
> - v1.5.84 起社区每张卡支持点赞与评论，列表可按「最新 / 热门 / 活跃」排序（热门 = 点赞×1 + 评论人数×3，同一人多条评论只计一次；活跃 = 最近 24 小时窗口内同一口径）；世界书详情不导入即可查看条目内容；记忆页的「世界书注入」静态行已移除（上限固定，无需展示）。
> - 第 7 章（Agent 设定同步）与第 8 章（比奇）为当前主线功能；第 3–5 章（用量/价格/AI 输出格式）仍适用。

## 一、变量系统

### 1.1 创建变量条目
1. 在世界书中点击「+ 添加条目」
2. 类型选择「变量」
3. 内容格式：每行一个变量，格式为 `变量名=初始值`

```
千纱好感度=50
千纱情绪=放松
雪性幻想值=30
```

### 1.2 创建前端条目
1. 在世界书中点击「+ 添加条目」
2. 类型选择「前端」
3. 内容写HTML，用 `{{变量名}}` 引用变量

```html
<div style="padding:10px; background:#1a1a2e; color:#fff; border-radius:8px;">
  <h3>{{千纱}}</h3>
  <div>好感度：{{千纱好感度}}/100</div>
  <div style="background:#333; height:8px; border-radius:4px;">
    <div style="width:{{千纱好感度}}%; background:#f472b6; height:100%;"></div>
  </div>
</div>
```

### 1.3 使用变量
1. 切换到「变量」标签页
2. 点击「初始化变量」加载变量
3. 续写时AI会自动输出 `[VAR]变量名=新值[/VAR]` 更新变量
4. 支持增减操作：`千纱好感度=+5` 或 `千纱好感度=-3`

## 二、条件注入

### 2.1 设置条件
1. 编辑世界书条目
2. 在「条件注入」字段输入条件
3. 格式：`变量名 操作符 值`

### 2.2 支持的操作符
- `>` 大于
- `<` 小于
- `>=` 大于等于
- `<=` 小于等于
- `=` 等于
- `!=` 不等于

### 2.3 示例
- `千纱好感度 > 70` → 好感度超过70时注入
- `雪性幻想值 >= 80` → 性幻想值达到80时注入
- `明日香情绪 = 心动` → 情绪为"心动"时注入

### 2.4 使用场景
- 好感度到达一定值时，注入亲密剧情条目
- 角色情绪变化时，注入不同的对话风格
- 解锁条件满足时，注入隐藏剧情

## 三、用量统计

### 3.1 查看统计
1. 切换到「用量」标签页
2. 上方显示累计统计（总调用次数、总字数、总费用、缓存命中率）
3. 下方显示最近10次续写的详细数据

### 3.2 数据说明
- **调用次数**：本次续写调用API的次数
- **字数**：生成的正文字符数
- **耗时**：从开始到完成的时间
- **输入tokens**：输入给AI的token数
- **缓存命中**：缓存命中率百分比
- **费用**：按配置价格计算的费用
- **输出速度**：输出 tokens ÷ 本轮总耗时（tokens/s）。分母含本轮全部 API 调用（续写 + 填表 + 二审等）的耗时，故略低于模型纯生成速度；累计卡片的「输出速度」为同口径合计值

### 3.3 清空历史
点击「清空历史」按钮可清空所有记录

## 五、AI输出格式

### 5.1 变量输出
AI在续写时会在开头输出变量更新：

```
[VAR]
千纱好感度=85
千纱情绪=害羞
[/VAR]

正文内容...
```

### 5.2 处理逻辑
1. 解析 `[VAR]...[/VAR]` 块
2. 更新变量值
3. 从正文中移除 `[VAR]` 块
4. 显示处理后的正文

### 5.3 思维链（思考标签）
1. 对没有原生推理通道的模型，引擎会要求它把思考写在 `<thinking>…</thinking>` 里、`</thinking>` 单独一行闭合，正文另起一行以 `【正文】` 开头；这两个标记都不会出现在正文里，思考进编辑器上方的蓝色折叠框。
2. **思考长度不受限制**（上万字也可以）——引擎只认标记边界，不做任何长度判定。
3. 模型忘记闭合思考标签时，这段内容**保留在思考框里**（不会混进正文）；正文区会显示一条提示条，点「移回正文」可把它并回正文。只有思考框本身不显示时（思维链关闭 / 该模型已停用思考框）才当作正文处理。
4. 若某模型连续两轮不闭合思考标签，引擎会判定它不吃标签协议，自动停止为它显示思考框（思考按正文处理），避免反复出现提示条。

## 六、提示词规则

### 6.1 变量规则（自动添加）
当世界书中有变量条目时，系统会自动在prompt中添加：

```
## 变量状态
千纱好感度=50
千纱情绪=放松

【变量输出规则·必须遵守】
每次回复必须在最开头输出变量状态块，格式如下：
[VAR]
变量名=新值
[/VAR]

然后空一行再写正文。变量值变化时写新值，未变化的变量也必须输出当前值。支持 +N/-N 增减操作。
```

### 6.2 条件注入规则
- 有条件且条件满足 → 注入条目
- 有条件但条件不满足 → 跳过条目
- 无条件 → 正常注入

> ⚠️ 条件注入机制已下线（见文首说明），本节仅作历史记录。

## 七、Agent 设定同步（AI 自动整理设定）

> 适用：App v1.5.49+。需在「插件」页开启「Agent 设定同步」。

### 7.1 它能做什么
续写正文之后，AI 会在**同一次调用内**把剧情中新出现、值得沉淀的设定以固定格式提议出来；系统攒批，攒够一次做一次**低温二审**，通过后写入一个按书隔离的**临时世界书**——原书设定永远不会被自动改动：

- 修改 → 覆盖式叠加（可展开看原值）
- 删除 → 软停用（只进 disabled 列表、不真删，可随时恢复）
- 新增 → 追加

所有变更可整体重置或逐批回滚。

### 7.2 工作流程
1. 续写（或手动「立即结算」）时，引擎在提示词尾部注入设定同步指令；
2. AI 在正文之后输出 `[SETTING_DELTA]` 提议块；无变更也必须输出空块 `[SETTING_DELTA][][/SETTING_DELTA]`；
3. 该块由引擎剥离：**不上屏、不进正文/归档**，只解析进「待裁决表」；解析失败静默丢弃（不打断正文，下一轮还有机会）；
   - 标记容错：模型写成 `[SETTINGS_DELTA]`、`[SERIES_DELTA]`、大小写混乱等变体时同样识别与剥离，不会漏进正文；
   - 漏写闭标记 / 输出被截断的半截块也会剥掉 JSON 载荷（保留块后可能存在的正文）；
4. 触发二审条件（任一）：待裁决满 5 条 / 距上次二审满 10 轮 / 待裁决超 20 条 / 切换章节；
5. 二审以「整理者」角色拿到 原条目完整内容 + 待裁决明细 + 正文依据（quote）→ 逐条 accept / merge / reject（可纠正错误目标 retarget）→ 落盘临时世界书并打快照、留历史日志。

### 7.3 查看与操作
- 在插件页/世界书查看页看到**合并视图**（原书 + 临时变更叠加后的效果）；
- 条目徽标：`临时新增` / `临时修改`（可展开原值）/ `临时停用`；未变更条目无徽标；
- 按钮：
  - **立即结算**：不等攒批，立刻把当前待裁决送去二审；
  - **重置**：清空本书全部临时变更与待裁决（原书零触碰）；
  - **回滚上一批**：撤销最近一次二审落盘（快照栈上限 5 批）；
  - **编辑**：改原书条目 → 写进临时层覆盖；改临时条目 → 直接改临时层；
- 待裁决卡片显示 op / 目标 / 内容预览 / 理由 / 正文依据（quote）；预览过长时点「展开全文」查看完整内容（存储上限为单条 4000 字，预览截断只是显示折叠、不影响实际数据）；
- 重置本书会连带清空本书的临时层与待裁决。

### 7.4 采纳门槛（防乱收）
- **新增（add）**最宽松：与原书/待裁决语义不重复即可；
- **修改（mod）**：必须有正文依据 quote 且与旧内容直接冲突；只收静态属性（年龄/外貌/性格/背景/身世/能力/职业/身份/阵营/关系），行为与单次情节事件不允许写进设定；
- **删除（del）**最严：仅角色死亡 / 势力覆灭 / 被新剧情明确推翻（带 quote）；离场、伏笔、单轮未提及一律不删；
- 单次情节事件（场景推进/对白/动作/单次决定）一律不收录——只有全局性、可复用的设定改变才收；
- 内容正确但归错条目（target 与内容不匹配）→ 二审纠正归属后采纳，而不是拒绝。

### 7.5 内容格式与常见问题
- AI 给出的 content 必须是**完整最终内容**（整合原条目 + 新设定后的全文），系统整体写入、不二次拼接；
- content 禁止写故事简介 / 章节总结 / 事件流水账；角色类条目须按字段清单（姓名/性别/年龄/外貌/性格/背景/能力/职业/身份/关系）组织，禁止散文段落与格式泄漏；
- 提议块缺失/解析失败：静默丢弃不打断正文；连续 2 轮无输出痕迹时系统会补交提醒一次（漏报自愈）；
- 二审后「没变化」：待裁决会保留、下轮继续尝试，不会清空丢失；
- 二审注入的上下文与正文续写一致（世界书合并视图 + 主角 + 登场角色 + 状态摘要 + 最近正文）；
- 缓存：提议指令与待裁决「覆盖指令」注入 user 滚动区（每轮变化的尾部），不破坏 system 前缀缓存命中。

### 7.6 数据位置
全部按书隔离，键前缀 `settingDeltaPending_ / settingOverlay_ / settingDeltaLog_ / settingOverlaySnaps_ / settingDeltaMeta_` + 书 ID，存于本地存储（StorageManager），不随社区分享上传；原书 `worldBooks` 数据自始至终不被写入。

## 八、比奇（对话式维护临时世界书）

> 适用：App v1.5.79+。需在「插件」页开启「比奇」。与「Agent 设定同步」**互斥**（两者维护同一份临时世界书，同时开启会互相覆盖，开启一方会自动关闭另一方）。

### 8.1 它是什么
正文页工具栏的「🛠️ 比奇」按钮 → 在正文上半屏开一个对话窗（只有 ✕ 能关，下半屏正文照常滑动）。和它讨论剧情该怎么走，它会按讨论结果**直接修订本书的临时世界书**：原书永远不动，改动立即生效（下一次续写就用上），并自动打快照，可在「临时世界书」页「回滚上一批」撤回。

### 8.2 它能做什么
- 读：当前生效的世界书（原书 + 临时层合并视图，标注哪些是临时改动）；最近正文（与续写注入的正文**同源**，`App.collectRecentStoryText`）；
- 写：新增条目 / 修改条目（给该条目的完整最终内容）/ 停用条目（软删除，可回滚）；
- 每轮工具调用在窗口里留痕（如 `📚 查看世界书 → 生效 31 条`、`✏️ 新增「器物·佩刀「灰烬」」 → 已加入临时世界书`）。

### 8.3 落盘语义（与自动同步同一套）
比奇的写入包成同一种提议（DeltaOp）走同一套落盘逻辑：add 命中已有条目自动并入而非重复建条、修改写临时层覆盖、删除原书条目走软停用；因此改名合并、快照、审计日志、合并视图徽标全部复用，不需要另学一套。

### 8.4 与 Agent 设定同步的分工
- **Agent 设定同步**：无人值守，续写后自动提议、攒批二审；适合「写完就不管」；
- **比奇**：对话式，你说改哪就改哪，改完立刻在窗口里看到理由与结果；适合「写到关键转折，想先理清设定再往下写」。

### 8.5 数据位置
同「临时世界书」：`settingOverlay_<书ID>` / `settingOverlaySnaps_<书ID>` / `settingDeltaLog_<书ID>`；对话历史按书隔离（`biqiHistory_<书ID>`）。原书 `worldBooks` 不被写入。

## 九、注意事项

1. **变量名**：建议使用有意义的名称，如「千纱好感度」
2. **初始值**：变量条目中的值只在变量不存在时生效
3. **前端渲染**：用 `{{变量名}}` 引用，支持HTML/CSS
4. **条件判断**：数值比较用数字，字符串比较用引号
5. **缓存命中**：变量和前端条目不注入prompt，不影响缓存
6. **世界书注入上限**：固定 10 万字（约 7 万 token），不再提供设置项——市面绝大多数模型的上下文都装得下，一本世界书基本能整本注入。超出时按「角色 > 世界观 > 其他」优先级取用、整条跳过，未注入条数在世界书页标题下显示。该上限只依赖条目本身，不会影响续写缓存命中。
7. **归档检索预算**：「记忆」页的「归档检索」控制检索开关与每次续写可注入的旧正文上限（默认 30000 字）。
8. **记忆页说明**：旧版「事件记忆」手动条目与分层摘要（段落/场景/章节摘要、伏笔抽取）已移除——长程记忆由「归档检索 + 相关档案（数据库）+ 角色状态」承担；需要长期保留的设定请写成世界书条目。
9. **正文窗口（字）**：「记忆」页可设常驻 prompt 的旧正文上限，默认 5 万字（≈ 3.6 万 token）。正文超过它的 1.5 倍时，最旧的部分自动滚入归档，原文保留、仍可被关键词检索回读。旧版的「最大上下文 tokens / 每 token 字符数」已移除：注入量不再按模型上下文窗口推导（默认 256k 会推出 17.9 万字窗口，光正文就喂 ≈12.8 万 token）。记忆页同时显示「正文窗口 + 世界书 + 回读」的本轮注入估算。
