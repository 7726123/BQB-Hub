# BQB Hub - 功能使用文档

> ⚠️ 本文档正在逐章校对（截至 2026-09）。前七章部分描述的是**已下线机制**：
> - 世界书条目类型为「世界观 / 角色 / 初始 / 其他 / 变量」（「开头」类型 v1.5.81 起废弃，存量开头条目自动移除）。其中「变量」是 **2026-09-26 起重新启用的新机制**（一个条目 = 一个变量，见第 0 章）：第 1 章「变量名=初始值 / 前端条目」、第 5.1 节「[VAR] 输出」、第 6.1 节「变量规则自动添加」描述的都是**旧机制**，入口已不存在；续写输出里的 `[VAR]` 块仍会被解析（老数据兼容），但界面上不再提供对应入口。
> - 「条件注入」机制已整体移除（第 2 章、第 6.2 节不再适用）：当前所有开启「注入」的条目一律注入上下文，由检索与注入上限控制取舍。
> - 社区聊天（频道 / WebSocket）v1.5.82 起整体下线，社区只保留世界书与预设；API 的 Max Tokens 设置项同版本移除（输出上限不再由用户设置，一律按端点能接受的最大值发送）；世界书注入上限固定 10 万字（见第九章第 6 条）。
> - v1.5.84 起社区每张卡支持点赞与评论，列表可按「最新 / 热门 / 活跃」排序（热门 = 点赞×1 + 评论人数×3，同一人多条评论只计一次；活跃 = 最近 24 小时窗口内同一口径）；世界书详情不导入即可查看条目内容；记忆页的「世界书注入」静态行已移除（上限固定，无需展示）。
> - 第 7 章（Agent 设定同步）与第 8 章（比奇）为当前主线功能；第 3–5 章（用量/价格/AI 输出格式）仍适用。

## 〇、变量（一个条目 = 一个变量）— 当前机制

### 0.1 它是什么

世界书里的**一个「变量」条目 = 一个变量**：

| 字段 | 含义 |
| --- | --- |
| 名称 | **变量名**（如「任务数量」「金钱」「H对象」）——面板、注入、收集全按这个名字走 |
| 内容 | **给模型的讲解**：这个变量是什么、怎么变化、范围或失败条件（可用 `{{user}}` 指代主角、`{{getvar::其它变量}}` 引用别的变量当前值） |
| 注入开关 | **单独启用/停用这一条**（关掉后这条既不再注入、也不再更新） |

想开 5 个变量就建 5 个条目（世界书列表里一条条开关）。变量名里不能有冒号或换行（回报格式按「名称：值」走）。

### 0.2 软件做什么（用户不用写这段）

每轮生成（续写与演出**都**注入）会在最后一条用户消息末尾附上：

- **格式契约**：正文写完后另起一行回报，按
  ```
  <status>
  任务数量：xx
  金钱：xx
  </status>
  ```
  一行一个，只写启用中的变量（值是清单时写在键行下面，每项一行）；
- **变量说明**：每个条目的名称 + 讲解 + 当前值（第一轮还没有值时，会提示模型给出符合讲解的初始值）。

回报块**不会留在正文里**：流式阶段就不上屏，收尾时按规则剥掉（容错：模型漏写标签、写成
`<状态栏>`/`<StatusBar>`、漏闭标记、只写「变量名：值」行都认）。模型某一轮漏写某个变量时，
那一条**保留上一轮的值**；回报了书里没有同名的键（模型自己加的字段）一律忽略——不显示、不入库，也不会干扰别的变量。
名字写法被模型改坏也能对上：漏括号（`手里的现金（日元=48000`）、半角括号、用等号当分隔符、名字被截短（`手里的现金：48000`）
都按唯一命中落回原变量；块外（模型漏写标签的兜底行）只认严格的名字，避免误吃正文。

### 0.3 怎么看

输入栏上侧空白条正中那个淡淡的**人字（∧）**（小说、对话两条输入栏各一个；旁边的小数字是本模式的变量条数）
→ 全屏「变量」面板：**纯查看**——节点顺序列出每个变量的名称、当前值、讲解与最后更新时间，没有切换/复制/清空/
编辑按钮（要改条目去世界书页；要清值就撤回那一轮或重置本书）。从哪个模式打开就显示哪个模式那一份，
面板标题下的状态行会写明「小说模式 / 对话模式」。

- **小说 / 对话各存一份**：同一本书两条剧情线的变量互不污染（与记忆表同惯例）。
- **撤回会一起回退**：撤回一次续写 / 一轮演出，变量也回到那一轮之前的值；**对话模式「清空演出记录」清对话那份、写作页「重置本书」两种模式一起清**（面板里不再有清空按钮）。
- **`{{getvar::变量名}}`** 能取到面板里的当前值（预设、世界书条目、主角设定里都能用）。

### 0.4 变量之间怎么"合作"：`{{getvar::变量名}}`

`{{getvar::名字}}` 是一个**文本替换宏**：发提示词前，软件把它就地换成那个变量的**当前字符串值**
（值取自「变量」面板；同名时，老变量表——预设导入的顶层 `variables`、`[VAR]` 累积值——优先）。

**能用在哪**：变量条目的讲解、世界书条目内容、主角设定、预设模块——凡是进提示词的地方都会被展开，
变量块本身也会。

**三个典型用法**
1. 让某段设定里出现"现在的数值"：条目里写「{{user}} 现在身上有 {{getvar::金钱}} 日元」
   → 模型每轮看到的就是最新值，不用手动同步。（注意：值一变这段文字的字节就变，从那里起的前缀缓存失效
   ——长书里别把它塞进每次都在变的条目。）
2. 让一个变量"引用"另一个：在 A 的讲解里写「本月剩余次数记在 {{getvar::任务数量}} 里」
   ——把关系写清楚，模型每轮同时看到两份讲解与当前值，会一起更新。
3. 给模型一个可读的当前锚点：预设尾部模块或主角设定里写「现在是 {{getvar::时间}}，在 {{getvar::地点}}」。

**它不做的事（重要）**：不做算术、不做条件判断、不触发更新。让「任务数量」和「时间」联动
（每月刷新、月底没做完判失败）的正确做法是**把规则写进讲解**，由模型每轮同时更新这两个变量；
软件只负责把值存下来、把宏替换掉。老的 `computed:` 表达式与条件注入（"变量>10 才注入这条"）
都已下线，见第 1、2 章的旧说明。

**兜底**：书里没有同名变量时，宏展开成**空字符串**——所以别把它放在关键句子里当保证；
要让它一定有意义，先建好同名「变量」条目。

### 0.5 边界（当前不做）

- 格式契约由软件固定（用户只写变量名与讲解）；值的形态在讲解里约定（例如「多个对象用 & 连接」）。
- 没有「初始值」字段：开局状态写在讲解里，第一轮由模型回报后进面板。
- 面板不能手改值；不支持条件注入（该机制已下线）。
- 「变量」条目不计入世界书 10 万字注入预算（它走消息末尾的专用通道，不参与条目优先级取舍）。

## 一、变量系统（旧机制，已下线：`变量名=初始值` 行、`前端` 条目、条件注入）

### 1.1 创建变量条目
1. 在世界书中点击「+ 添加条目」
2. 类型选择「变量」
3. 内容格式：每行一个变量，格式为 `变量名=初始值`

```
千纱好感度=50
千纱情绪=放松
雪性幻想值=30
```

### 1.2 创建前端条目
1. 在世界书中点击「+ 添加条目」
2. 类型选择「前端」
3. 内容写HTML，用 `{{变量名}}` 引用变量

```html
<div style="padding:10px; background:#1a1a2e; color:#fff; border-radius:8px;">
  <h3>{{千纱}}</h3>
  <div>好感度：{{千纱好感度}}/100</div>
  <div style="background:#333; height:8px; border-radius:4px;">
    <div style="width:{{千纱好感度}}%; background:#f472b6; height:100%;"></div>
  </div>
</div>
```

### 1.3 使用变量
1. 切换到「变量」标签页
2. 点击「初始化变量」加载变量
3. 续写时AI会自动输出 `[VAR]变量名=新值[/VAR]` 更新变量
4. 支持增减操作：`千纱好感度=+5` 或 `千纱好感度=-3`

## 二、条件注入

### 2.1 设置条件
1. 编辑世界书条目
2. 在「条件注入」字段输入条件
3. 格式：`变量名 操作符 值`

### 2.2 支持的操作符
- `>` 大于
- `<` 小于
- `>=` 大于等于
- `<=` 小于等于
- `=` 等于
- `!=` 不等于

### 2.3 示例
- `千纱好感度 > 70` → 好感度超过70时注入
- `雪性幻想值 >= 80` → 性幻想值达到80时注入
- `明日香情绪 = 心动` → 情绪为"心动"时注入

### 2.4 使用场景
- 好感度到达一定值时，注入亲密剧情条目
- 角色情绪变化时，注入不同的对话风格
- 解锁条件满足时，注入隐藏剧情

## 五、AI输出格式

### 5.1 变量输出
AI在续写时会在开头输出变量更新：

```
[VAR]
千纱好感度=85
千纱情绪=害羞
[/VAR]

正文内容...
```

### 5.2 处理逻辑
1. 解析 `[VAR]...[/VAR]` 块
2. 更新变量值
3. 从正文中移除 `[VAR]` 块
4. 显示处理后的正文

### 5.3 思维链（思考标签）
1. 对没有原生推理通道的模型，引擎会要求它把思考写在 `<thinking>…</thinking>` 里、`</thinking>` 单独一行闭合，正文另起一行以 `【正文】` 开头；这两个标记都不会出现在正文里，思考进编辑器上方的蓝色折叠框。
2. **思考长度不受限制**（上万字也可以）——引擎只认标记边界，不做任何长度判定。
3. 模型忘记闭合思考标签时，这段内容**保留在思考框里**（不会混进正文）；正文区会显示一条提示条，点「移回正文」可把它并回正文。只有思考框本身不显示时（思维链关闭 / 该模型已停用思考框）才当作正文处理。
4. 若某模型连续两轮不闭合思考标签，引擎会判定它不吃标签协议，自动停止为它显示思考框（思考按正文处理），避免反复出现提示条。

## 六、提示词规则

### 6.1 变量规则（自动添加）
当世界书中有变量条目时，系统会自动在prompt中添加：

```
## 变量状态
千纱好感度=50
千纱情绪=放松

【变量输出规则·必须遵守】
每次回复必须在最开头输出变量状态块，格式如下：
[VAR]
变量名=新值
[/VAR]

然后空一行再写正文。变量值变化时写新值，未变化的变量也必须输出当前值。支持 +N/-N 增减操作。
```

### 6.2 条件注入规则
- 有条件且条件满足 → 注入条目
- 有条件但条件不满足 → 跳过条目
- 无条件 → 正常注入

## 七、Agent 设定同步（AI 自动整理设定）

> 适用：App v1.5.49+。需在「插件」页开启「Agent 设定同步」。

### 7.1 它能做什么
续写正文之后，AI 会在**同一次调用内**把剧情中新出现、值得沉淀的设定以固定格式提议出来；系统攒批，攒够一次做一次**低温二审**，通过后写入一个按书隔离的**临时世界书**——原书设定永远不会被自动改动：

- 修改 → 覆盖式叠加（可展开看原值）
- 删除 → 软停用（只进 disabled 列表、不真删，可随时恢复）
- 新增 → 追加

所有变更可整体重置或逐批回滚。

### 7.2 工作流程
1. 续写（或手动「立即结算」）时，引擎在提示词尾部注入设定同步指令；
2. AI 在正文之后输出 `[SETTING_DELTA]` 提议块；无变更也必须输出空块 `[SETTING_DELTA][][/SETTING_DELTA]`；
3. 该块由引擎剥离：**不上屏、不进正文/归档**，只解析进「待裁决表」；解析失败静默丢弃（不打断正文，下一轮还有机会）；
   - 标记容错：模型写成 `[SETTINGS_DELTA]`、`[SERIES_DELTA]`、大小写混乱等变体时同样识别与剥离，不会漏进正文；
   - 漏写闭标记 / 输出被截断的半截块也会剥掉 JSON 载荷（保留块后可能存在的正文）；
4. 触发二审条件（任一）：待裁决满 5 条 / 距上次二审满 10 轮 / 待裁决超 20 条 / 切换章节；
5. 二审以「整理者」角色拿到 原条目完整内容 + 待裁决明细 + 正文依据（quote）→ 逐条 accept / merge / reject（可纠正错误目标 retarget）→ 落盘临时世界书并打快照、留历史日志。

### 7.3 查看与操作
- 在插件页/世界书查看页看到**合并视图**（原书 + 临时变更叠加后的效果）；
- 条目徽标：`临时新增` / `临时修改`（可展开原值）/ `临时停用`；未变更条目无徽标；
- 按钮：
  - **立即结算**：不等攒批，立刻把当前待裁决送去二审；
  - **重置**：清空本书全部临时变更与待裁决（原书零触碰）；
  - **回滚上一批**：撤销最近一次二审落盘（快照栈上限 5 批）；
  - **编辑**：改原书条目 → 写进临时层覆盖；改临时条目 → 直接改临时层；
- 待裁决卡片显示 op / 目标 / 内容预览 / 理由 / 正文依据（quote）；预览过长时点「展开全文」查看完整内容（存储上限为单条 4000 字，预览截断只是显示折叠、不影响实际数据）；
- 重置本书会连带清空本书的临时层与待裁决。

### 7.4 采纳门槛（防乱收）
- **新增（add）**最宽松：与原书/待裁决语义不重复即可；
- **修改（mod）**：必须有正文依据 quote 且与旧内容直接冲突；只收静态属性（年龄/外貌/性格/背景/身世/能力/职业/身份/阵营/关系），行为与单次情节事件不允许写进设定；
- **删除（del）**最严：仅角色死亡 / 势力覆灭 / 被新剧情明确推翻（带 quote）；离场、伏笔、单轮未提及一律不删；
- 单次情节事件（场景推进/对白/动作/单次决定）一律不收录——只有全局性、可复用的设定改变才收；
- 内容正确但归错条目（target 与内容不匹配）→ 二审纠正归属后采纳，而不是拒绝。

### 7.5 内容格式与常见问题
- AI 给出的 content 必须是**完整最终内容**（整合原条目 + 新设定后的全文），系统整体写入、不二次拼接；
- content 禁止写故事简介 / 章节总结 / 事件流水账；角色类条目须按字段清单（姓名/性别/年龄/外貌/性格/背景/能力/职业/身份/关系）组织，禁止散文段落与格式泄漏；
- 提议块缺失/解析失败：静默丢弃不打断正文；连续 2 轮无输出痕迹时系统会补交提醒一次（漏报自愈）；
- 二审后「没变化」：待裁决会保留、下轮继续尝试，不会清空丢失；
- 二审注入的上下文与正文续写一致（世界书合并视图 + 主角 + 登场角色 + 状态摘要 + 最近正文）；
- 缓存：提议指令与待裁决「覆盖指令」注入 user 滚动区（每轮变化的尾部），不破坏 system 前缀缓存命中。

### 7.6 数据位置
全部按书隔离，键前缀 `settingDeltaPending_ / settingOverlay_ / settingDeltaLog_ / settingOverlaySnaps_ / settingDeltaMeta_` + 书 ID，存于本地存储（StorageManager），不随社区分享上传；原书 `worldBooks` 数据自始至终不被写入。

## 八、比奇（对话式维护临时世界书）

> 适用：App v1.5.79+。需在「插件」页开启「比奇」。与「Agent 设定同步」**互斥**（两者维护同一份临时世界书，同时开启会互相覆盖，开启一方会自动关闭另一方）。

### 8.1 它是什么
正文页工具栏的「🛠️ 比奇」按钮 → 在正文上半屏开一个对话窗（只有 ✕ 能关，下半屏正文照常滑动）。和它讨论剧情该怎么走，它会按讨论结果**直接修订本书的临时世界书**：原书永远不动，改动立即生效（下一次续写就用上），并自动打快照，可在「临时世界书」页「回滚上一批」撤回。

### 8.2 它能做什么
- 读：当前生效的世界书（原书 + 临时层合并视图，标注哪些是临时改动）；最近正文（与续写注入的正文**同源**，`App.collectRecentStoryText`）；
- 写：新增条目 / 修改条目（给该条目的完整最终内容）/ 停用条目（软删除，可回滚）；
- 每轮工具调用在窗口里留痕（如 `📚 查看世界书 → 生效 31 条`、`✏️ 新增「器物·佩刀「灰烬」」 → 已加入临时世界书`）。

### 8.3 落盘语义（与自动同步同一套）
比奇的写入包成同一种提议（DeltaOp）走同一套落盘逻辑：add 命中已有条目自动并入而非重复建条、修改写临时层覆盖、删除原书条目走软停用；因此改名合并、快照、审计日志、合并视图徽标全部复用，不需要另学一套。

### 8.4 与 Agent 设定同步的分工
- **Agent 设定同步**：无人值守，续写后自动提议、攒批二审；适合「写完就不管」；
- **比奇**：对话式，你说改哪就改哪，改完立刻在窗口里看到理由与结果；适合「写到关键转折，想先理清设定再往下写」。

### 8.5 数据位置
同「临时世界书」：`settingOverlay_<书ID>` / `settingOverlaySnaps_<书ID>` / `settingDeltaLog_<书ID>`；对话历史按书隔离（`biqiHistory_<书ID>`）。原书 `worldBooks` 不被写入。

## 九、注意事项

1. **变量名**：建议使用有意义的名称，如「千纱好感度」
2. **初始值**：变量条目中的值只在变量不存在时生效
3. **前端渲染**：用 `{{变量名}}` 引用，支持HTML/CSS
4. **条件判断**：数值比较用数字，字符串比较用引号
5. **缓存命中**：变量和前端条目不注入prompt，不影响缓存
6. **世界书注入上限**：固定 10 万字（约 7 万 token），不再提供设置项——市面绝大多数模型的上下文都装得下，一本世界书基本能整本注入。超出时按「角色 > 世界观 > 其他」优先级取用、整条跳过，未注入条数在世界书页标题下显示。该上限只依赖条目本身，不会影响续写缓存命中。
7. **归档检索预算**：「记忆」页的「归档检索」控制检索开关与每次续写可注入的旧正文上限（默认 30000 字）。
8. **记忆页说明**：旧版「事件记忆」手动条目与分层摘要（段落/场景/章节摘要、伏笔抽取）已移除——长程记忆由「归档检索 + 相关档案（数据库）+ 角色状态」承担；需要长期保留的设定请写成世界书条目。
9. **正文窗口（字）**：「记忆」页可设常驻 prompt 的旧正文上限，默认 5 万字（≈ 3.6 万 token）。正文超过它的 1.5 倍时，最旧的部分自动滚入归档，原文保留、仍可被关键词检索回读。旧版的「最大上下文 tokens / 每 token 字符数」已移除：注入量不再按模型上下文窗口推导（默认 256k 会推出 17.9 万字窗口，光正文就喂 ≈12.8 万 token）。记忆页同时显示「正文窗口 + 世界书 + 回读」的本轮注入估算。

## 十、真实模式（多角色各自独立记忆的演出）

第三个视图：和小说、对话是**同一本书**的三个视图（顶部书名共用）。和对话模式最大的不同是**一轮只有一个人说话**，而且每个角色的内心与记忆**各自独立维护**——TA 不在场时发生的事，TA 真的不知道：不是"要求模型别说"，而是那部分内容**根本不会发给 TA**。

1. **开局**：**直接点「▶ 继续」**——时间、地点、在场名单都由「场记」自己维护（开场也由它定），不需要你先配置；要手工纠正就用场景栏的「⚙ 场景」。
2. **以谁的身份说话**：输入框上方有一个下拉栏——选「上帝模式」，或选本模式已加入的任意角色；旁边的「＋ 添加角色」可以从当前世界书里的任意「角色」条目把人加进来（加进来会同时进入当前场景）。这个模式**没有固定扮演者**，也不涉及主角。
3. **推进**：输入框**留空直接点发送＝让剧情自己走**（按钮显示「▶ 继续」）——这是最常用的用法；有话说就直接写。回车发送、Shift+回车换行。
4. **说话与动作**：和对话模式同一套约定——你写的话以**当前选中那个角色**的身份说出去，（括号里）写动作和神态。**你说的那句会先被 AI「转述」成这个角色规范的一轮**：台词补上「」、动作去掉括号和"我"、你写成"（心里想着…）"的部分收进 `<内心>`。转述**只做整理，不改你的意思**（零碎、有错别字、分不清哪句是台词哪句是心里话，它负责顺通），而且**只有它整理过的那部分才会被别的角色看到**——这就是"哪些话别人该听到"的判定点。气泡下面会有一个「✎ 已整理 · 看原话」，点开能看你原本打的字（撤回也会把原话放回输入框）。转述没走通（超时/接口报错）就照原话发出，不会卡住这一轮。
5. **上帝模式**：下拉切到「上帝模式」后，你写的是**客观事实**（例：「第二天，千纱没有到校」），在场的人都会经历到；它不替任何人发言。
6. **谁说下一个**：由「场记」看着场景、在场名单和刚发生的事判断（也可以什么都不说，只推环境）；**你刚用谁说过话，软件就不会安排 TA 替你接话**。想指定谁就用下拉切过去。
7. **心里话**：角色没说出口的心理活动放在 `<内心>…</内心>`，**你看得到、戏里别的人看不到**（不会进别人的上下文）；你直接写「（心里想着…）」也行，转述会替你收进 `<内心>`。低声/私下说话会被判成"只有对方知道"，其他人只看到一句壳（"两人在低声交谈"）。
8. **记忆**：每个角色只记得自己经历过的事（不在场就是空白，别人转述给他才算知道）；长局里软件会把较早的经过折成 TA 自己的回忆（≤250 字，阈值用「记忆」页的「正文窗口」，不裁字）。台词/旁白/内心都存原文，导出与归档沿用写作模式的规则。
9. **大家都知道的事（公开通知/传闻）**：场记每轮顺手维护一份（「下周六开运动会」「明天停课」这类**客观上公开**的事），**发给每一个角色，不管他当时在不在场**。悄悄话、私下的心思永远不会进来。想看或想改（比如开局就先播一条设定）就打开「⚙ 场景」，里面有一栏「大家都知道的事」，改完下一轮以你这份为准。
10. **谁知道什么**（真实模式的信息差一共四条通道，按"多少人知道"分）：
    - **「角色」条目** = 公开人设，人人都知道；
    - **「初始记忆」条目** = **只有一个人**知道（1 对 1 绑一个角色，写他自己的秘密）；
    - **「部分人知道」条目** = **一个小组**知道、别人不知道（名称=一句话标题，内容=这件事本身，**知情者=列出所有知道的人**）。作者额外设定的、"从剧情里推不出来"的隐情（比如"两人初中就认识，一直瞒着班上的人"）就写这里；
    - **「大家都知道的事」** = 客观上公开的通知/传闻，由场记每轮自己维护（见上一条）。
    前三条都是**硬隔离**：名字不在名单里的角色，**那部分内容根本不会出现在 TA 的请求里**（场记、别的角色、常规世界书注入都拿不到）。
11. **撤回与清空**：输入行左侧「↶ 撤回」把上一轮连同场景变化一起回滚，你打的那句回到输入框；场景栏的「清空」把这本书的真实模式记录、场景**和输入栏里的内容**一起清掉（参演名单和你在扮演的角色保留，世界书不动）——和对话模式的「清空」同一套收尾。
12. **角色资料怎么写**：世界书「角色」条目 = **别人都看得到的公开人设**；**秘密、隐情、"谁知道什么"写进「初始记忆」或「部分人知道」条目**（初始记忆一个人一条、1 对 1；部分人知道列知情者名单）。写卡 agent 也按这条来。
13. **预设**：格式契约由软件给定；**真实模式默认不吃预设**——只有「适用模式」标了「仅真实」的模块才生效（导入的小说/群像预设是"续写+演出都用"，不会进来）。场记那次调用一点预设都不吃，只有角色调用吃「仅真实」的模块。
