# ADR-0001：世界书条目注入模型精简为单一开关

- 状态：已采纳（v33）
- 日期：2026-08

## 背景

世界书条目最初支持「常驻/条件注入」双机制 + 「关键词注入」自动匹配：条目可配置 alwaysInject、
keywords 列表，系统按关键词命中决定是否注入。另有「AI 精简」按钮对长条目做摘要压缩。
新增条目的默认行为是**常驻关闭**（必须手动打开才注入）。

v32 之后秘密条目体系被移除。v33 评估时发现：关键词注入、条件注入的匹配代码已无真实调用方
（前端 UI 已删但后端逻辑残留），且「默认不注入」导致用户新建条目后经常忘记打开开关，
续写时设定缺失。

## 决策

1. 删除「AI 精简」「条件注入」「关键词注入」「秘密条目」全部逻辑与 UI。
2. 条目只保留一个布尔字段 `inject`：**新建条目默认 `inject: true`**，手动关闭才不注入；
   `undefined` 一律视为注入（兼容旧数据）。
3. 开头/初始类型条目无开关、永远不注入（它们由章节开头逻辑单独处理）。
4. 导出时兜底写入 `inject = true`，导入时兼容旧字段并丢弃 keywords/alwaysInject。

## 后果

- 正面：概念面从 4 个机制减到 1 个；注入管线可读性大幅提升；
  稳定前缀（始终注入的条目）序列固定，利于 prompt 缓存友好。
- 负面：失去按关键词动态裁剪的能力，超长条目列表会占更多上下文
  （缓解：条目数与长度由用户自控；后续可用 token 预算策略再回收）。
- 迁移：存量数据 `inject === undefined` 视为注入，无需数据迁移脚本。
