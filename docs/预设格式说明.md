# BQB Hub — 原生预设格式说明

> 本文档定义本软件（Capacitor Android 版 BQB Hub）的**原生预设格式**，并给出
> 「如何把 SillyTavern（酒馆）预设翻译成原生预设」的完整流程与示例。
>
> 适用版本：2026-08-18 起（代码已回退为**不内置酒馆适配**的原始版本；
> 原生预设导入 + 正则跟随预设为唯一新增能力）。
>
> 校对：2026-09-09——世界书条目类型已收敛、思考处理已演进，见 §5/§8/§9 的修订标记。
>
> **推荐工作流**：酒馆预设 → 交给外部 AI（如 zcode）按本文档翻译成原生预设 JSON → 直接导入本软件使用。
> 本软件**不做**酒馆格式的强行适配，翻译工作交给 AI 完成。

---

## 0. 快速上手：把酒馆预设交给外部 AI 翻译

这是推荐的使用方式。把下面这段话 + 本文档 + 你的酒馆预设 JSON 一起发给外部 AI（如 zcode），
让它产出一个**原生预设 JSON 文件**（用代码块输出，方便你保存为 `.json` 后导入）：

```
你是一个预设翻译器。请把附件中的 SillyTavern（酒馆）预设翻译成本软件的「原生预设格式」。

翻译要求（必须严格遵守）：
1. 认真阅读《原生预设格式说明》文档，按其中定义的 promptModules / variables /
   regexScripts 结构输出。
2. prompts[] → promptModules[]：
   - content 保留原文，name 保留原名，enabled 保留，role 保留（system/user/assistant）；
   - 只保留 enabled 的模块；prompt_order 中显式 enabled:false 的模块（三选一备选等）
     一律剔除；
   - 剔除纯废话模块（如"指令收到"确认类）。
3. 模板语法保留原样：{{user}} / {{setvar::K::V}} / {{getvar::K}} / {{//注释}} / ${...}。
4. setvar 声明尽量收敛：把散落在各模块里的 {{setvar::K::V}} 合并进顶层 variables 对象，
   模块内保留 {{getvar::K}} 引用即可。
5. extensions.regex_scripts[] → regexScripts[]：
   - **只保留文本处理类**（replaceString 是纯文字，如"…、"、去"-"号）；
   - **丢弃一切 HTML 美化类**（replaceString 含 <div>/<details>/<style> 等 —— 写作工具
     不需要聊天美化UI，注入会污染正文并可能卡死）；
   - 丢弃 promptOnly=true 的脚本；
   - findRegex 保持原样（/pattern/flags 或裸串），timing 用 after（处理模型输出）。
6. 顶层 assistant_prefill / squash_system_messages：写作场景不需要，丢弃。
7. variables：把预设依赖的运行时变量（地点/时间/好感度等）提出来放顶层 variables，
   给出合理初始值。
8. 输出物：完整 JSON（不要省略、不要用"……"占位），字段见示例。
```

AI 输出后：保存为 `.json` → 打开本软件「导入预设」→ 选择文件 → 检查模块/正则/变量是否齐全 → 生成测试。

## 1. 设计原则

本软件是**小说写作工具**，不是聊天角色扮演工具。因此预设的本质是：

```
预设 = 系统提示词（模块化） + 变量（运行时状态） + 文本正则（输出清洗） + 采样参数
```

- 与酒馆的最大区别：**不承载聊天前端**（状态栏、选项按钮、猫尾巴等 HTML 美化不属于写作工具）。
- 模型执行的规则（人设、文风、破甲、格式、梳理）都是**纯文本**，写入模块即可完整生效。
- 预设是**自包含的**：切换预设时，它的模块、变量、正则一起生效。

## 2. 预设对象结构

一个预设就是一个 JSON 对象，存于 `StorageManager('presets')` 数组。字段如下：

```json
{
  "id": "preset_1720000000000_abcd",
  "name": "示例工作室·写作版",

  "promptModules": [
    {
      "id": "uuid 或自定义标识",
      "name": "模块名（界面显示）",
      "content": "模块正文（发送给模型的文本）",
      "enabled": true,
      "role": "system",
      "order": 0
    },
    {
      "id": "mod_cot",
      "name": "思维链·标准",
      "content": "……先梳理六步，再动笔……",
      "enabled": true,
      "role": "user",
      "slot": "think",
      "order": 17
    }
  ],

  "sampler": {
    "temperature": 1,
    "topP": 0.95,
    "presencePenalty": 0,
    "frequencyPenalty": 0,
    "reasoningEffort": "medium"
  },

  "variables": {
    "当前地点": "示例工作室 3 楼茶水间",
    "当前时间": "深夜 23:40"
  },

  "regexScripts": [
    {
      "id": "regex_xxx",
      "name": "统一省略号",
      "findRegex": "\\.\\.\\.+",
      "replaceString": "……",
      "timing": "after",
      "enabled": true
    }
  ],

  "assistantPrefill": "",
  "squashSystemMessages": false,

  "systemPromptId": null,
  "isDefault": false,
  "createdAt": 1720000000000
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，代码生成 |
| `name` | string | 预设名 |
| `promptModules` | array | **模块化提示词**（核心）。system 模块按 `order` 拼进最前面的系统提示词；user 模块按 `order` 拼进最后一条用户消息末尾（见 §3） |
| `variables` | object | 预设附带的初始变量，导入时写入当前世界书变量表 |
| `regexScripts` | array | **预设自带文本正则**，切换预设时自动生效（不与其它预设共享） |
| `assistantPrefill` | string\|null | **兼容字段，当前版本不读取**（没有 assistant 预填充通道） |
| `squashSystemMessages` | bool | **兼容字段，当前版本不读取**（消息条数由软件按缓存最优自己决定） |
| `sampler` | object | **预设自带的采样参数**（temperature / topP / presencePenalty / frequencyPenalty / reasoningEffort），切预设即生效（见 §7） |
| `systemPromptId` | string\|null | 关联旧式单条系统提示词（兼容旧用法） |

## 3. promptModules 详解

模块是预设的主体。生成时的装配顺序是固定的：
**system 模块（按 `order`）→ 世界书/角色 → 正文或演出记录 →【指令】+ user 模块（按 `order`）**。
即：`enabled` 的 system 模块按顺序拼成最前面的系统提示词；`role: "user"` 的模块不影响它，
而是拼进**最后一条用户消息的末尾**（贴着生成点）。模块内容之间以空行分隔。

### 3.1 字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `id` | 自动 | 模块唯一标识；从酒馆导入时=原始 `identifier` |
| `name` | 自动取首行 | 界面显示名 |
| `content` | — | **正文**，支持模板语法（见 §4） |
| `enabled` | true | 是否发送。界面勾选框可切换 |
| `role` | `system` | **去处（位置）**：`system` = 拼进最前面的系统提示词（世界书、历史之前）；`user` = 贴到最后一条用户消息的末尾（历史之后、贴着生成点）。酒馆的 `assistant` 条目导入时归一到 `system`（没有预填充通道） |
| `slot` | — | 仅 `role: "user"` 有意义：`"think"` = 这条讲思考要求（"思考多长、怎么记、何时停"），思考强度关闭或无原生推理通道时**整条不下发**，且它的存在会抑制软件兜底思考条款。界面上的类型「user（思维链）」即 `role:user + slot:think` |
| `order` | 索引 | 排序号（无导入顺序时的回退排序） |
| `mode` | 续写 + 演出都用 | `novel` / `chat` / `real` 限定只在一个模式生效（界面「适用模式」：只用在续写模式 / 只用在演出模式 / 仅真实）。**`both`（含缺省）不进真实模式**：真实模式只吃显式标 `real` 的模块 |

> **真实模式（`real`）的预设边界（2026-09-28）**：真实模式的**格式契约由软件给定**
> （公共调用「场记」+ 角色调用两张契约，见 `app/src/domain/realprompt.ts`），预设不必也不该写输出格式。
> 「场记」那一次调用**不吃预设**（它是机械契约、只做场景维护与选人）；**作者那句的「转述」调用也不吃预设**
> （只做规范化，同样由软件给定契约）；**角色调用才吃预设**：
> `role:system` 的模块拼进系统提示词，`role:user` 的模块（含 `slot:think`）贴在末尾。
> **真实模式默认不吃预设**：只有把「适用模式」选成「仅真实」的模块才会生效——导入的酒馆预设大多是
> 「续写+演出都用」，它们不会进真实模式（否则小说/群像那套规则会把"一轮只扮演一个人"直接盖掉，2026-09-28 实测）。
> 内容只放文风、语气、协议这类东西，别让预设输出状态栏、自检、选项这类格式块（与写作模式同一条规矩）。

### 3.2 位置与「包裹」语义（2026-09-26）

- 类型名就是去处：界面的 **`system`** / **`user（思维链）`** / **`user（末尾·非思维链）`** 三种标签，
  分别对应 `role:system`、`role:user + slot:think`、`role:user`。写模块时**不需要**（也不能）声明
  "放在历史之前/之后"——位置由软件负责。
- 酒馆 `prompt_order` 的位置语义**不实现**：`injection_position: 1` + `injection_depth`（把某块插进
  历史中间/深处）在本软件里只按 `order` 顺序生效；`dialogueExamples`（示例对话）也不注入。
  导入后请把依赖"深度注入"的条目改写成 system 模块，或接受顺序语义。
- 因此酒馆预设里的 `<dream_setting>` / `<dream_history>` 这类**包裹标记**在本软件里包不住任何东西：
  它们只是普通文本模块（通常落在 user 槽），可以直接停用/删除；需要向模型解释容器名时，
  另加一条「上下文对照」system 模块即可（见 §10 的梦鲸示例）。
- 多数酒馆预设的条目是 `role:system`（设定/文风/协议都在系统侧）；把"越靠后越管用"的要求
  （思考要求、格式重申、禁词）放 user 槽。两侧的顺序都按 `order` 生效。

### 3.3 推荐写法（写作工具友好）

把"人设 / 文风 / 破甲 / 格式 / 梳理 / 附加模块"分成独立模块，便于开关：

```json
[
  { "name": "📌人设", "content": "……角色设定……", "enabled": true },
  { "name": "🎨文风", "content": "……文风要求……", "enabled": true },
  { "name": "🔥破甲", "content": "……允许题材/禁止审查……", "enabled": true },
  { "name": "📐格式", "content": "……输出格式：标题/正文/分段……", "enabled": true },
  { "name": "🧠梳理", "content": "……生成前梳理要求……", "enabled": true }
]
```

> 提示：写作工具建议把"梳理"类要求写清楚（模型会用思考通道，见 §9），
> 模型输出的思考会自动折叠进蓝色「思考」框，不占正文。

## 4. 模板语法（模块 content 内可用）

生成前统一展开（`_expandSTInMessages` → `lib/stmacros.ts`）。**按消息顺序逐条展开**（与酒馆 prompt_order
一致）：先出现的 `setvar/addvar` 对后面生效；值里嵌套的宏会**递归展开**（限 8 层）。

| 语法 | 含义 | 示例 |
|---|---|---|
| `{{user}}` / `{user}` / 裸 `user` | 主角名（裸 user 按独立单词匹配，`username` 不动） | `{{user}}走进办公室` |
| `{{char}}` / `{{charIfNotGroup}}` | 其他角色 | `{{char}}对{{user}}说` |
| `{{setvar::KEY::值}}` | 赋值（声明被移除，值供 getvar 用） | `{{setvar::当前地点::示例工作室}}` |
| `{{addvar::KEY::值}}` | **追加**到同名变量（"可多开"的次要文风/禁词/协议那种写法） | `{{addvar::文风::再加一句}}` |
| `{{getvar::KEY}}` | 取值（未定义→查世界书运行时变量→空） | `所在地：{{getvar::当前地点}}` |
| `{{getglobalvar::KEY}}` / `{{setglobalvar::KEY::值}}` | 全局变量（本软件映射到世界书运行时变量） | `{{getglobalvar::主题}}` |
| `{{lastUserMessage}}` | 本轮作者输入（酒馆里=最后一条用户消息） | `<dreamer_input>{{lastUserMessage}}</dreamer_input>` |
| `{{trim}}` | 删掉自己，并对整条消息 trim | 变量声明块收尾 |
| `{{random::甲\|乙,丙}}`（也支持 `1-5`） | 随机取一个 | `{{random::清晨\|黄昏}}` |
| `{{//注释}}` | 注释（被删除，不进 prompt） | `{{//此段不发送}}` |
| `${描述文字}` | 占位符外壳（去掉 `${}` 保留内部文字） | `正文至少${五百}字` → `正文至少五百字` |

> 不认识的宏（如酒馆扩展的 `{{压缩相邻消息::…}}`）**原样保留**发出去（酒馆里也是交给扩展/正则处理）。
> `{{setvar}}` 值的定界按**嵌套计数**（值里嵌 `{{getvar::x}}` 不会被内层 `}}` 提前截断）。

## 5. 变量系统

变量承载**运行时状态**（地点、时间、好感度、剧情状态），让模型保持剧情连贯。

### 5.1 三种来源

1. **世界书变量表**（主要来源）：运行时值按书隔离存储在变量表（StorageManager 键 `wbVariables`，
   不占世界书条目），支持 `computed:表达式`。例：`当前章节=3` / `等级=computed:3+1`。
   旧版「变量」类型世界书条目（每行 `key=value`）仍兼容读取为初始值来源（2026-08 起条目类型收敛，
   已无法新建该类型条目，见 §8）。
2. **预设 `variables` 字段**：导入原生预设时合并进当前世界书变量表（同名不覆盖已存在的）。
3. **模型输出 `[VAR]` 块**：模型在回复末尾输出：
   ```
   [VAR]
   当前地点=示例工作室天台
   好感度=+5
   [/VAR]
   ```
   生成后自动解析并更新变量（`+N/-N` 为增减）。`[VAR]` 块不会进入正文。

### 5.2 界面

「世界书 → 变量」面板可查看/编辑/初始化/清空全部变量。旧版「前端」类型条目（`{{变量名}}` 渲染卡）
与「变量」类型条目均已无法新建（条目类型新增入口收敛为 世界观/角色/开头/初始/其他），存量条目兼容保留。

## 6. 文本正则（regexScripts）

用于**输出清洗**（把模型输出规整成正文），全程**只做文本处理，不注入 HTML**。

| 字段 | 说明 |
|---|---|
| `findRegex` | 匹配串。支持 `/pattern/flags` 写法（推荐，flags 常用 `g`）或裸字符串 |
| `replaceString` | 替换文本。`{{match}}` 表示整段匹配（等价 `$&`），可用 `$1` 等捕获组 |
| `timing` | `before`：处理用户输入指令；`after`：处理模型输出（主要用途） |
| `enabled` | 是否启用 |

**导入酒馆预设时，它自带的 `extensions.regex_scripts` 会自动搬进来**（2026-09-26 起）：
只搬「给读者看」的纯文本规则（按 `placement` 落 timing：含 2＝AI 输出 → `after`，只含 1＝用户输入 → `before`）；
**跳过**三类——`replaceString` 里带 HTML/CSS 的「美化」脚本（本软件是纯文本编辑器，塞进去会当正文显示一堆样式）、
`promptOnly` 的「只对模型历史生效」脚本（本软件没有历史楼层机制）、以及酒馆里本来就关着的。
**文本正则跟预设绑定**（2026-09-26 起）：预设自带 `regexScripts` → 切到它就用它这套；
切到不带正则的预设 → 自动还回「你自己的那套」（首次绑定时把当时的规则存一份当基准，**重启后也算数**；
明显来自其它预设的规则（id 以 `st_`/`mjr_` 开头、或与某个预设的规则逐字相同）不会被当成你的基准存下来）。
也就是说：换预设就换这套正则，不需要手动去正则面板删删改改；
但你在正则面板里的手动编辑在"当前预设自带正则"时会被该预设的规则覆盖（面板只对不带正则的预设是你的地盘）。

导入完成的提示会写明「文本正则 N 条（跳过 M 条：HTML 美化 x / 提示词专用 y / 已关闭 z）」。

示例（写作常用，含本软件内置默认规则）：

```json
{ "findRegex": "\\.\\.\\.+", "replaceString": "……", "timing": "after", "enabled": true },
{ "findRegex": "/[“”\"\"]/g", "replaceString": "「", "timing": "after", "enabled": true },
{ "id": "regex_debagu", "name": "去八股词", "findRegex": "/(由于|极其|特么|踏马|引以为傲|可笑|甚至|引以为豪|死死地|无比坚定地|极度)/g", "replaceString": "", "timing": "after", "enabled": true }
```

> 本软件内置「去八股词」为默认规则（默认词表，可在正则面板自行增删/改名），版本更新后会自动补全
> 缺失的默认规则，不会清掉你自定义的规则。

> ⚠️ **禁止**：`replaceString` 里不要放 HTML（`<div>`/`<details>`/`<style>` 等）。
> 写作工具不需要聊天美化；注入 HTML 会污染正文且有卡死风险。

## 7. 采样参数

导入酒馆预设时，预设自带的采样参数会**一起存进预设**（`sampler`），切预设即生效
（`PresetManager.getEffectiveAPIConfig()` 把预设的 sampler 合到全局配置之上）：

| 预设字段 | 生效方式 |
|---|---|
| `temperature` / `top_p` / `presence_penalty` / `frequency_penalty` | 有值就以预设为准（**0 也生效**——旧版 `\|\| 默认值` 会把 0 吞成 0.4/0.3） |
| `reasoning_effort` | 映射成思考档位（minimal/low→low，medium→medium，high/max→high，none→off）；**用户在「思考强度」里显式选过就以用户为准**，没选过（auto）才跟预设 |
| `openai_max_tokens` | **不跟**：本软件一律按端点能接受的最大值发（防预设里 30000 这类值把长思考/长正文截断） |

原生预设也可以手写 `sampler: { temperature: 1, topP: 0.95, presencePenalty: 0, frequencyPenalty: 0, reasoningEffort: 'medium' }`；
不写就是全局配置。

## 8. 世界书集成

写作工具的"记忆"来自世界书（WorldBook）：

- 世界书条目类型新增入口（2026-08 起收敛）：**世界观 / 角色 / 开头 / 初始 / 其他**；早期类型
  （事件/设定/地点/伏笔/关系/物品/时间/变量/前端）在存量条目上兼容展示与读取，新建时不再提供选项。
- 注入模型（ADR-0001）：条目单一「注入」开关，默认注入；「条件注入 / 关键词 / 常驻」机制已移除，
  开启注入的条目一律注入正文上下文（受预算上限控制）；「初始」在正文为空时单独注入一次（开局快照），正文开始后不再注入。
- 原生预设建议**搭配一份世界书**使用：设定、角色等放世界书，行为规则放预设模块。

## 9. 思考（思维链）处理

- 引擎按模型能力分流思考：**原生推理通道**（reasoning_content，deepseek/kimi/qwen 等）与**文本思考标签**
  （`<think>` / `</thinking>` / HTML 注释 `<!-- 梳理：... -->`）都会折叠进蓝色「思考」框（`cot-thinking`），不占正文。
- 无原生推理通道的模型：引擎会**自动**在指令尾部追加标签协议（`<thinking>` 独占一行闭合 → `【正文】` → 正文），
  预设只需写「先梳理什么」（纯文本步骤），不要自己指定标签名。
- 有原生推理通道的模型：思考走通道，预设里出现标签字样反而会把正文诱导弹进思考，**预设文本中不要出现思考标签**。
- 「思维链」开关与「思考强度」档位在「高级设置 → AI 与生成 / 预设与生成」里配置；思维链关闭时不注入思考协议也不建思考框，等到正文才开始出字。不同模型走不同通道，同一模型请勿混用多种思考标签写法。
- 判断依据：预设文本里出现 `梳理：` / `writing_process` / `<!-- 梳理` 即视为「预设要求先梳理」，
  无原生推理的模型会拿到硬协议（内置「轻小说·最小预设」的思维链模块即按此写法）。
- **思维链归谁写（2026-09-26，酒馆对齐）**：预设自带思维链时**不再叠加**软件兜底条款。判定＝本模式有启用的
  「思维链」模块（模块类型选 `user（思维链）`，即 `role:user + slot:think`），或模块内容含思维链骨架（`<thought_of_chain>` /
  `<thinking_step` / `【思维模式要求】` / `【思维链要求】` / `【思考要求】`）。
  只**引用**思维链的模块（如「写作模式」里写 `</thought_of_chain>`）不算。
  导入酒馆预设时，含骨架的 user 条目会自动标成 `slot: 'think'`（思考关闭 / 无原生推理通道时不下发）。
  两边都写会出现"≤2000 字、别发散"和"按 N 步走完、逐字输出开篇"同时下发 → 思考长度忽长忽短（实测）。

## 10. 如何把酒馆预设翻译成原生预设

按 **§0 的提示词**把酒馆预设 JSON 交给外部 AI（如 zcode）翻译，即可得到可直接导入的
原生预设 JSON。手动翻译的映射规则如下（AI 翻译时也应遵守）：

| 酒馆字段 | 原生映射 | 处理 |
|---|---|---|
| `prompts[]`（角色提示项） | `promptModules[]` | `identifier→id`，`name→name`，`content→content`，`enabled→enabled`，`role→role`（`user` 进 user 槽＝消息末尾；`assistant` 归一到 `system`）。**空内容的标记项**（Char Description / World Info before·after / Persona / Scenario / Chat History / Chat Examples）直接跳过 |
| `prompt_order[0].order[]` | 排序次序 | 启用项按 `order` 排列；**`enabled:false` 的项剔除**（三选一备选）。`injection_position=1` + `injection_depth`（深度注入）**不实现**，只按顺序生效（见 §3.2） |
| `extensions.regex_scripts[]` | `regexScripts[]` | 仅保留**文本类**；HTML 美化类、`promptOnly:true` 类、酒馆里已关闭的丢弃；导入后**跟预设绑定**（见 §6） |
| 顶层 `assistant_prefill` | — | 丢弃（本软件没有 assistant 预填充通道，☆Gemini/☆Kimi 那类预填充条目不要保留） |
| 顶层 `squash_system_messages` | — | 丢弃（本软件自己决定消息条数） |
| `extensions.SPreset`（ChatSquash 等） | — | 丢弃（聊天专用，写作不需要） |
| 采样参数（`temp`/`top_p`/惩罚项/`reasoning_effort`） | 预设自带的 `sampler` | 导入时自动带进预设，**切预设即生效**（见 §7）；`max_tokens` 不跟预设 |
| 世界书/变量（摇杆等） | 世界书变量 | 整理成「变量」条目（见 §5） |

### 翻译步骤（5 分钟）

1. 在酒馆导出预设 JSON。
2. 打开本软件「导入预设」选该文件 → 自动翻译（跳过 HTML 美化 / promptOnly / 已关闭的脚本，采样参数一并带进预设）。
3. 导入后到「模块」面板检查：关掉不需要的模块，开启想要的（如文风三选一里选一个）；
   类型（system / user（思维链） / user（末尾·非思维链））就是模块的去处，位置不用自己写。
4. 到「正则」面板确认导入的文本正则（默认已按文本规则启用；切预设会自动换成该预设自带的那套）。
5. 到「世界书」补建变量条目、设置初始值。
6. 采样参数不用手抄：导入时就存进了预设，切到这个预设即生效（见 §7）。
7. 生成测试：检查思考是否进蓝框、正文是否正常、正文里有没有残留的状态栏/外壳标签（见 §3.2 与 §6）。

## 11. 与旧格式的关系

- 旧式「系统提示词」（`systemPrompts`，单条大文本）仍然支持，作为无模块时的回退。
- 新原生格式与旧格式共存：`promptModules` 为空时使用 `systemPromptId` 指向的旧提示词。
- 从酒馆导入的预设同时保留 `promptModules`（新）与 `sysprompt`（旧备用）。

## 12. 常见问题

**Q1：导入酒馆预设后生成卡顿/内容消失？**
A：请确认已用最新 APK（2026-09，v1.5.5x+）。历史版本可能受"HTML 美化正则误导入"影响；
旧版正则会在启动时自动清理。必要时重新导入一次预设。

**Q2：想用酒馆的状态栏/选项按钮？**
A：写作工具不渲染聊天 UI，这些美化不适用。对应正则已被跳过（导入日志有提示）。
若确需保留部分 HTML 结构进入正文，请手动在「正则」面板添加（自担卡顿风险）。

**Q3：模型不输出我要求的内容？**
A：先在「模块」面板确认该模块 enabled；再确认 `prompt_order` 里没有把它标 `enabled:false`（即"三选一"备选被作者关掉了）；最后看「思考」框里模型的梳理是否照做。

**Q4：变量不更新？**
A：检查世界书「变量」条目是否存在；模型需在回复末尾输出 `[VAR]…[/VAR]` 块；
若模型没输出，可在变量「规则」条目中添加"变量更新规则"引导。
